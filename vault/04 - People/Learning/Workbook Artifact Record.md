# Workbook Artifact Record

The 96-page workbook uses three passes: read concepts, complete practice, convert a reviewed exercise into a bounded build. It asks operators to use one real product/node per exercise and produce inspectable specs, diagrams, code stubs, prompts, tests or decisions.

## Record
| Field | Complete |
|---|---|
| Learner / role | Actual participant and assigned track |
| Source edition / module / page | Drive ID and exact exercise |
| Terms to explain | Definitions still unclear |
| Source-system map | Product, owner, workflow, data, agent and tool relationships |
| One open question | Evidence required before implementation |
| Practice artifact | Spec, diagram, code, prompt or test record |
| Prototype boundary | First useful low-risk result and exclusions |
| Expected / observed behavior | Test and actual result |
| Governance | Aegis class, reviewer and blocked actions |
| Review decision | Accepted work, gap and next assignment |

## Progression
Start with dashboards, agent specifications, graphs, workflow diagrams and passive Pi shells before drones/robotics. Physical movement remains held for safety review. Log decisions in the Knowledge Keeper format.

The source recommends marking unexplained terms, identifying systems repeated across documents and writing a question per page. This form captures that work without claiming that reading alone earns a certificate. See [[Learning Reference Editions]] and [[Project Delivery Record Template]].
