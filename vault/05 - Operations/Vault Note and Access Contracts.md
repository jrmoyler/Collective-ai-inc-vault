# Vault Note and Access Contracts

## Architecture reconciliation
The source v2.0 describes a historical 11-folder master vault and 20 independent division vault designs. Its June 2026 target of about 190 notes and 37 completed notes is a historical snapshot. The current application has 13 storage districts and six additional thematic views; these views do not create new companies or move canonical notes. The campus retains six physical districts.

## Minimum note record
Capture note type, tags, source reference and record date. Projects carry status, actual owner, deliverables, due date when assigned and Aegis level. Decisions carry context, options, rationale, actual decision authority, status and review date when assigned. Division references separate launch and ARR targets from measured results. Agent records identify current tier, division, tool contracts, memory policy, evaluation rubric and prompt version. Do not infer an owner or deadline from a template.

## Capture and processing
Read the existing note and search related titles before adding material. Keep a capture source attached, distill a reusable fact or decision into its canonical note, and append only a missing section. Link the relevant division and MOC, then add the reciprocal MOC link. Preserve superseded versions with their date and replacement reference. Projects connect milestones, deliverables and decision records; daily notes connect priorities, wins, blockers, learning and agent health.

## Division access design
The source treats division vaults as independent silos. Read access is scoped to context, identity, tools and precedent; proposed write access is limited by note class, such as evaluation logs, milestone updates, daily summaries and decision records. Cross-division access requires the current approved authorization path. These are design requirements, not proof that isolation or agent access has been deployed. Do not widen access because a thematic view links both divisions.
