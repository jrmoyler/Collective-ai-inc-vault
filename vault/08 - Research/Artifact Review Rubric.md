# Artifact Review Rubric

Use the curriculum's eight review questions to evaluate proof-of-work. This is a review form, not a claim that existing projects pass.

| Category | Review question | Evidence |
|---|---|---|
| Correctness | Does it work and match the source? | Observed result and source section |
| Completeness | Does it cover scope and edge cases? | Acceptance criteria and remaining gaps |
| Inspectability | Can another builder explain and test the change? | Diff, rationale and reproduction steps |
| Design | Is it clear, accessible, responsive and branded? | Screens, keyboard checks and viewport evidence |
| Code | Is it organized, typed, tested and maintainable? | Relevant checks and module boundaries |
| AI | Are outputs structured, validated and evaluated? | Cases, failures, grounded answers and versions |
| Governance | Are privacy, Aegis, security and escalation covered? | Reviewer decision and trace |
| Operational fit | Can the team use it in real work with little editing? | Actual workflow run and recipient review |

## Review record
Artifact / owner / source/version / requirement / expected result / observed result / test environment / reviewer / accepted gaps / next action.

Record findings rather than unsupported numeric grades. If a team later adopts a scoring scale, include its definition and approval in the record. Link [[Team Learning Path and Competency Gates]], [[Project Delivery Record Template]] and [[Evidence Record Template]].
