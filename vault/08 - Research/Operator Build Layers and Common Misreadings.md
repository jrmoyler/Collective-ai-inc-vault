# Operator Build Layers and Common Misreadings

The COMPLETE studybook explains seven build layers. They are a source architecture map, not an inventory of verified running services.

| Layer | Domain |
|---|---|
| L0 | Human intent: operators, clients, learners and users |
| L1 | User experience: sites, apps, dashboards and devices |
| L2 | Workflows: forms, triggers, approvals and handoffs |
| L3 | Agents: research, planning, evaluation and orchestration |
| L4 | Intelligence infrastructure: prompts, tools, retrieval, memory, graphs and observability |
| L5 | Data infrastructure: schemas, databases, storage, queues and streams |
| L6 | Physical infrastructure: compute, networking, sensors and power |

## Five source corrections
1. Agents are reasoning components within workflows; workflow sequence, permissions and human handoffs still need design.
2. Grounded retrieval can still fail. Evaluate source filtering, retrieval and citations instead of assuming RAG eliminates unsupported answers.
3. Added agents introduce cost, latency and coordination surfaces. Give each agent a specific job and evidence of value.
4. Design controls comprehension, trust and review. Confidence displays and explanation surfaces are part of safe operation.
5. Physical AI requires identity, permissions, logs, maintenance, shutdown behavior and ownership, beyond buying hardware.

## Review use
For one real build, map its intent, screen, workflow, agent, retrieval/tool layer, data store and physical dependencies. Identify the missing layer before expanding feature scope. Use [[Artifact Review Rubric]] and [[Workflow Delivery Record Template]].
