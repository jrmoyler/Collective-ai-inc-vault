# Prompt Evaluation Record

The Prompt Engineering Compendium is labeled First Edition 2025, while its foreword is signed January 2026. Preserve both date signals. Its fifty techniques are research/practitioner references, not a guarantee of performance on current models.

## Technique families
Foundational reasoning; verification and correction; constraints/output specification; perspectives/comparison; reflection; knowledge augmentation; decomposition/orchestration; optimization; specialized/contextual tasks; combined workflows.

## Experiment form
| Field | Record |
|---|---|
| Task | Observable required output and constraints |
| Technique/source | Exact name, section and primary research citation |
| Template/version | Prompt revision and approved inputs |
| Baseline | Prior method evaluated on the same cases |
| Evaluation set | Cases, expected outcomes and data-use approval |
| Output checks | Schema, source support, completeness and policy |
| Results | Observed passes/failures; no invented improvement percentage |
| Cost/latency | Actual measurement and environment |
| Failure analysis | Unsupported claims, missed constraints and tool errors |
| Decision | Keep, change or reject with reviewer |

## Source method
Define the task, choose relevant techniques, prepare the prompt, test/refine and deploy only after evaluation. The source gives each technique an overview, template, research foundation, use cases, limits and combinations. Evaluate the underlying claim rather than assume the summary proves it.

Store answer evidence and concise decision summaries; the evaluation record does not require exposure of private model reasoning. Use [[Campaign Evidence Register]], [[Artifact Review Rubric]] and [[LLM Engineering Practice Path]].
