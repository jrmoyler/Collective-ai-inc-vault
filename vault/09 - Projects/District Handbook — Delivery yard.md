# District Handbook — Delivery yard

## District purpose
A project has a bounded outcome, an acceptance check, and a visible next action. Notes contain delivery evidence, while tasks manage work assignment.

Folder: 09 - Projects. This handbook describes the virtual knowledge district, not a physical campus district.

## Work kit
- Use a project brief with problem, scope, dependencies, acceptance criteria, milestone evidence, and open decisions.
- Link the owning division and related product; include current repository or deployment only when verified.
- For collaboration spanning divisions, identify the contribution of each participating division; the current Synergy Mandate requires at least three active divisions per engagement.

## Required record fields
- Outcome and scope
- Acceptance criteria
- Dependencies and work records
- Milestone evidence, blockers, and next action

## Completion check
- The source and its effective date are recorded.
- Current facts and historical targets are distinct.
- Linked division and hub notes exist.
- The next action or unresolved question is stated.
- An existing note is extended before a duplicate is created.
