# Website Production Checklist

The Drive checklist defines ten production sections and 85 checks. Apply the full source to each client build; the grouped checklist below preserves the concrete work categories and evidence requirements.

## 1. Discovery and strategy
- [ ] Capture goals, audience, competitors and tone.
- [ ] Define the site's one job and primary action.
- [ ] Agree on measurable success, pages and each page's purpose.
- [ ] Audit supplied brand assets and collect approved content.
- [ ] Confirm domain ownership/transfer, host, timeline and review/sign-off process.

## 2. Brand and identity
- [ ] Set dominant/accent/neutral colors using 60:30:10 per section.
- [ ] Select display, body and optional monospace type roles.
- [ ] Collect SVG logo with dark/light variants.
- [ ] Define 4px/8px spacing and visual tone.
- [ ] Review 3–5 visual references.
- [ ] Supply favicon, touch icon and 1200×630 social image.
- [ ] Choose a consistent icon system.

## 3. Approved copy
- [ ] Lock headline, subheadline and descriptive CTA label.
- [ ] Write specific biography, services and applicable prices.
- [ ] Use real approved testimonials, photos and case studies; never fabricate proof to meet a source's quantity target.
- [ ] Give each page metadata, contact/footer content and a useful branded 404.
- [ ] Audit all copy against [[JR Voice Standard]].

## 4. UX architecture
- [ ] Map arrival, conversion and exit.
- [ ] Make navigation understandable; the source targets at most 5–6 primary items.
- [ ] Review mobile layout and CTA placement above fold, mid-page and footer.
- [ ] Approve wireframes before visual polish.
- [ ] Define labels, validation, success, focus, hover, empty, loading and error states.

## 5. Visual quality
- [ ] Remove placeholder copy.
- [ ] Establish H1/H2/body/caption hierarchy and purposeful section treatment.
- [ ] Crop, compress and place images in context.
- [ ] Review 1440, 1024, 768 and 375px widths.
- [ ] Define entrance/scroll/hover/exit motion and one signature visual moment.
- [ ] Test body-text contrast against the source's 4.5:1 target.

## 6. Technical implementation
- [ ] Confirm stack and design tokens; source prefers Next.js App Router unless justified otherwise.
- [ ] Use reusable components and appropriately sized images/fonts.
- [ ] Wire forms to a real authorized endpoint and test their actual result.
- [ ] Keep environment secrets server-side.
- [ ] Provide page metadata, social tags, canonicals, robots and sitemap.
- [ ] Implement 404/error pages, approved analytics and remove unused dependencies.

## 7. Performance and search targets
| Source target | Acceptance evidence |
|---|---|
| Lighthouse performance ≥90 | Dated mobile and desktop run |
| LCP <2.5s | Actual measured run |
| CLS <0.1 | Actual measured run |
| INP <200ms | Applicable interaction measurement |

These are source targets, not measured results for any existing application. Optimize below-fold image loading, image format, font subsets and blocking scripts. Add relevant schema, one primary H1 and useful internal links.

## 8. Accessibility
- [ ] Meaningful alt text; decorative images have empty alt.
- [ ] Complete keyboard path with visible focus and skip link.
- [ ] Labels on inputs, semantic structure and necessary ARIA.
- [ ] Meaning never depends only on color.
- [ ] Source Lighthouse accessibility target ≥95 is tested and recorded.

## 9. Launch QA
- [ ] Test every navigation, CTA, footer and external link.
- [ ] Submit the form and verify the recipient/confirmation.
- [ ] Test Chrome, Firefox, Safari and Edge.
- [ ] Record real iPhone and Android tests separately from emulation.
- [ ] Confirm HTTPS, one canonical www direction, social previews and console results.
- [ ] Proofread and obtain client walkthrough/sign-off.

## 10. Launch and handoff
Verify DNS and search-console setup, preserve the tested production revision, document operation and authorized access, and record final handoff against the original source. Do not label deployment, client approval or physical-device QA complete without evidence.
